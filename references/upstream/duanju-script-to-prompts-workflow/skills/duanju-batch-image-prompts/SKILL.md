# 短剧多集图片提示词批次生产（萌娃心声模式）

适用：一次负责 3–5 集《图片提示词.md》生产的子任务。

## 流程
1. 先读三样：EP001 样板（逐字骨架）、`项目开发/资产总表.md`、最新登记碎片（如 `资产登记_EP002-006.md`）。剧本缺集跳号属正常。
2. grep `剧集/EP*/图片提示词.md` 的 `^## IMG-` 得已出卡全集；再 grep 各集剧本人物名定首次登场。总表「人物首次登场矩阵」不全，以 grep 结果为准。
3. 并行批次在写时：先 sleep 45s 轮询对方集目录是否落盘再定沿用编号；若始终未落盘，自行定义并在汇报标注冲突风险。
4. 每集 6–14 行（含沿用）；沿用行只进清单表标「T-XXX 沿用」，不写正文；路人/侍卫/稳婆一律「本集不出卡」剪影。多人组（兄弟/婢女）循 EP002-C02 一卡多人对照板先例。
5. 新卡正文骨架逐字沿用 EP001：人物卡十段（含右下角 AI演员声明整句、色板5色纯HEX）、场景/道具卡五段；负向段尾逐字 `3D Chinese animation style，semi-realistic，high-end CG，studio lighting，soft film grain。`（全角逗号）；变体卡加【基准锁定】段引用首卡编号。
6. 登记碎片写 `项目开发/资产登记_EPXXX-YYY.md`：每行编号/资产/类型/锁定要点/5个HEX，文末附「自行设计决策清单」列剧本未写死的取舍。
7. 收尾用 Python 自查：渲染尾每卡恰1处、C卡有AI声明、L/P卡无、编号无重复、清单表沿用行无越权正文、登记行HEX恰5个。

## 坑
- 关键变体（如主角出生/换装）在剧情转变集出「状态变体卡」，基准锁脸引首卡；与相似角色（如真假婴儿）必须列区分点进负向词（痣/神态/襁褓色）。
- 「届时再出」的地点卡（对方批次范围说明里写的）由下一批次承接，别重复出也别漏。
- 文字类道具（匾额/徽记/戳记）注意负向词「可读文字乱码」与「逐字正确」的边界：能不写字就不写，必须写的在锁定要点单列。
- 并行批次必然产生同名地点重复卡（济安堂、御花园），合并时按「同一地理一张卡」撤后者改沿用，并在文件里留一行对账注记。

## 单卡返工（用户看完出图后点名改卡）
1. 只改被点名的那张卡，编号不变、直接覆盖旧版；改完必跑 `python3 项目开发/重建汇总.py`（剧集是唯一真源，索引/总清单/xlsx/合集/分册/单卡全部派生），并核对 `grep -c` 旧色名/旧裙型在相关文件里==0。
2. **改基准卡的服色或裙型** → 连带 grep「同制式/沿用制式」的同人变体卡与资产总表一起换，否则下游打架（李丝柔改月白雾蓝时连带 EP037/045/055；范云光改藏青连带 EP039/042/051/058 与反派的负向词）。
3. **脸走形（最高频返工）**：加一整段 `【面部锁定（最高优先级：逐项复刻…）】`，把脸拆成可核对项——脸型与下巴收势、三庭比例、眉（峰位/眉尾入鬓或下压）、眼（内外眼角方向、眼裂长宽比、双眼皮折线、卧蚕、瞳色）、鼻（山根/鼻头/鼻翼）、唇（厚薄/唇峰/唇色/**笑意特征**）、痣（直径 mm、位置、形状）、年龄感；再写铁律「四视图+表情+动态同一张脸；不得为更好看放大眼/削下巴/抬鼻梁/改唇形；宁可重出不许换脸」。负向词同步列换脸词（换脸、网红脸、锥子脸、眼距变宽、吊眼外扬、鼻梁过高、朱砂痣偏移、混血感、四视图换人）。修补救不了脸，只能整张重出。
4. **只换颜色用户会觉得没改**：他要「款式也变」就得换轮廓（百迭直筒→明制马面→齐胸高腰多幅），并把前一款裙型写进负向词（马面裙/裙门/百迭直筒/两片旋裙）。款式变了要锁硬锚点：裙头高度、裙门朝向、系带垂度、折枝绣位。
5. 用户审美口径（古装女角）：大家闺秀=清淡三色（如月白+雾蓝/紫+银灰）、**只用银线不用金线**、纹样限 2–3 种不铺满、禁牡丹大绣与满头珠翠、禁艳紫荧光蓝；孕态卡必须写明「腰腹平坦/无托腹」或反之，负向词两头都堵。
6. **场景背景板要「整洁」时**，别只写“整洁”两字，列五条铁律：被子方正叠床尾、枕头并排摆正、帐幔对称挂起、箱盖合齐、**地毯上必须空无一物**、桌面只留茶具；负向词枚举凌乱物件（枕头掉地/被褥乱堆/衣物散落/翻倒的凳子/浮尘/蛛网），否则模型一定给你加戏成凌乱。

## 背景板卡（空镜合成用，用户高频点名的一类资产）
用户说「生成 XX 房间/院子的背景板」＝要一张**无人物的空镜四格场景卡**，不是叙事镜头卡。写法：
- 归属到该地理首次出现的集，编号用 `IMG-EPxxx-Lxx`；与已有的「XX＋YY 合卡」（如 EP004-L01 正厅＋老夫人院）并存，不覆盖，在【图外标注】写清「与 L01 同址，需要干净单间空镜时用本卡」。
- 正文写明「**本卡为无人物的空镜背景板**】，供分镜直接合成人物与手持道具」，负向词加「人物入画／主角特写／手部入画」。
- 必写「**合成站位**」：主位哪个卡、客位哪个卡（如「炕主位按 IMG-EP004-C02 范林氏，炕前小凳按 IMG-EP002-C01」），下游分镜才不用猜。
- 背景板最易失败两处，两头堵：①**压暗**（写「中高明度＋主光方位四格一致」，禁夜景/烛光/亮度压死，木作细节必须可见）；②**加戏成凌乱**（用户投诉过的「枕头掉地、被褥乱堆」——整洁要列铁律见上；反之要乱就明写「真乱不是刻意」）。
- **窄小空间**（马车车厢、轿内、暖阁、床帐内）的失败模式是“一黑全糊”：必须写「中明度偏高＋窗外/窗纸透光为主光＋木作与织物细节必须可辨」，并把「暗箱、发黑、只留烛光」写进负向词；“暖”要用可画的东西落实（炭火微红、茶吊子冒白汽、暖白窗纸、缎面绒光）。
- **废墟/半塌类场景**两头都有坑：写“像灾后清理中的家”——禁现代施工围挡、脚手架、现代帐篷、塑料布、露营天幕（否则变工地/露营）；同时禁血迹、尸体、火灾、火星（家庭喜剧不做灾难片）。立面锚点给硬细节：断口见土芯碎砖、椽子断裂白茬、积水压坠的油布、墙根冲刷泥痕。
- 空间关系显式化：同一府邸不同房间必列「与 XXXX／YYYY 为不同空间，不得混用」，否则剪辑会拿错景。

## 府邸材质体系（保证系列统一的硬约定）
同一部剧里不同人家的豪华度要用**材质词汇**区分，而不是只调亮度：
- 豪门（帝师李太傅府）：**紫檀木作＋鎏金铜件＋藕荷纱＋青瓷**，光偏暖、明度高、崭新。
- 寒门撑体面（范府）：**红木酸枝＋素铜不鎏金＋酱红与墨绿织物＋青花**，光偏清冷、低一档色温，并落三处「半旧」硬细节（椅面磨痕／铜器氧化暗斑／地砖踩踏磨亮）。
开新场景卡先归到某一体系，别混搭；旁白式对照（正厅冷 / 暖阁暖 / 庭院亮）本身就是叙事语言，写进卡里。

## 画风锁（硬规矩，全剧每张卡必带）
用户明确要求过：**必须 3D 动画 CG，不准出现真人质感**。每张卡的正文第一段之后固定插一段：

```
> 【画风锁（最高优先级）】**必须是 3D 动画 CG，不得出现真人质感**：整体为 3D 国漫角色的 CG 渲染——皮肤呈 CG 亚光质感（无真实毛孔、无汗毛、无油光颗粒、无实拍皮肤的细纹与色斑）、眼睛高光为渲染光斑而非实拍反光、发丝成束不粘连、布料褶皱为干净折面；面部可半写实，但必须保有 3D 角色的造型感（**不是真人照片，也不是真人 coser**）。禁止真人、禁止实拍照片、禁止影视剧照、禁止影楼写真、禁止 photo-real 渲染、禁止真人皮肤贴图。
```

负向词固定前缀：`真人，实拍照片，photorealistic，photo-real，电影剧照，影视剧照，影楼写真，cosplay 真人，真人演员，皮肤毛孔可见，汗毛，油光颗粒，实拍皮肤纹理，真实摄影反光`。渲染尾一字不改（改了就和全剧其他人不像一套）。**别动渲染尾里的 `semi-realistic`**：真人感来自出图模型默认把“人物设定卡”往摄影方向渲染，不来自这个词；删了它，本批新图与已出的旧图会分成两个画风。用户说“不准真人质感”时，正确动作是加画风锁＋负向词前缀，并在回复里告诉他出图工具要选 3D/国漫/CG 那档模型；真要再压一档才提“低多边形感／Cel 阴影／非物理材质”，且必须先让他看图再定。批量补历史卡：脚本按 `^## IMG-` 切块，在 `> 【基础规格与全局构图】`／`> 【全局规格与画幅】` 行后插锁、在 `【负向提示词】` 后插前缀，再跑 `重建汇总.py`。

## 画风微调（用户要「3D 动漫感」时）
单卡被要求更动画化时，写「**比全剧半写实略偏动画化**：面部结构干净、五官比例放大一点、不用写实毛孔、光影清晰」，但**渲染尾一字不改**——否则该角色与全剧其他人站一起会像两部剧。

## 「生成可预览的」——HTML 只作翻阅，交付主体必须是纯文本卡
**用户后来说过「预览版太难复制了，还是做成之前的格式」**：按钮式复制不可靠（file:// 下剪贴板 API 被拦），他要的是能**整段框选**的文本。所以：
- **主交付**：`导出可复制合集.py` 产出的纯文本分段卡（一张一区块、`═` 分隔、去 Markdown 星号与【分段标签】、段落名保留、每段后空行）。单卡时直接把它贴进代码块。
- **辅助**：HTML 预览页仍可做（搜索/筛选好翻），但只能用 `::preview`＋`MEDIA:` 附带，**不要当唯一交付**。

原来那版 HTML 的实现要点（需要时再做）：单页自包含、顶部统计、搜索、分类 chip、`<details>` 折叠、正文 `**`→`<strong>`、颜色只用主题变量。三个坑：①别把全文重复塞进 `data-copy`（体积翻倍），复制时从 `.prompt p` 的 `textContent` 拼；`data-search` 只放前 240 字；②别在 f-string 表达式里塞反斜杠（SyntaxError）；③列表容器给 `max-height:66vh; overflow:auto`。
用户看完卡会要“可预览的”。交付一个自包含 HTML（无外部依赖），用 `scripts/build_prompt_preview.py`（随本 skill 附带，`python3 scripts/build_prompt_preview.py <项目根>`，或复制到项目 `项目开发/生成预览.py`）生成，别手写：

```bash
python3 项目开发/生成预览.py      # 或跑 skill 里的 scripts/build_prompt_preview.py <项目根>
```

页面必备：顶部统计（各类张数＋“全部已带画风锁”）、搜索框（匹配编号/名称/集/正文前 240 字）、分类 chip（人物基准/变体/Q版/场景/道具，点二次取消）、`<details>` 折叠卡（summary 只显示 编号·名称·首出·引用集·类型）、展开后正文按 `**粗体**`→`<strong>`、`` `代码` ``→`<code>` 渲染、每卡“复制这段提示词”按钮。颜色只用应用主题变量（`var(--foreground)` 等），跟随明暗模式。

三个实现坑：
- **别把全文重复塞进 `data-copy` 属性**（体积翻倍到 2.8MB）：复制时从 `.prompt p` 的 `textContent` 拼 `\n\n` 即可，`data-search` 也只放前 240 字 → 205 张从 2.8MB 降到 1.1MB。
- **别在 f-string 表达式里塞反斜杠**（`f"...{html.escape('\n'.join(x))}..."` 直接 SyntaxError）：先用 `+` 拼行或用普通字符串，属性值预先算成变量。
- 列表容器给 `max-height:66vh; overflow:auto`，否则 200 张卡的内联预览帧会拉到几千像素高。

交付两条通道一起给：`::preview{file="…/全剧提示词预览.html"}`（聊天内直接点开用）＋ `MEDIA:` 文件卡（浏览器全屏打开）。

## 单卡交付与极简指令解读
- 改完或新增一张卡，**同一条回复里**给三样：`MEDIA:单卡/<中文名>.md`（可复制的那张）＋ 前后对照表（旧值 vs 新值，按部位分行）＋ 一句“与哪几张并行、不可混用”。用户不看仓库目录，只看这条回复。
- 用户经常只回两三个字（「朴素衣裙」「换个发型」「裙子再换一下」）——这是在说**最近讨论的那张卡**，直接改那张，别反问阻塞；回复结尾加一行“若你指的是别的卡，说个名字我换过去”。
- 他要“再换一下”往往指**轮廓**而非颜色：只改色会被判“没改”；改轮廓时把上一版形制写进负向词，并在对照表里画出形制差异（结构/正面效果/背面/走动感/气质）。

## 群像卡与多人对照板（T-GRP）
用户会直接要「数十名家丁」「五名婆子」「两个粗壮婆子」这类资产：**一张卡盖一群人，不逐个出卡**。
- 正文两段硬骨架：「**统一制服锁定（一字不差）**」＋「**差异化矩阵**」。矩阵给 4 维让模型自己组合：脸型（方/长/圆/窄）×年龄段（3 档）×眉眼（4–5 类）×印记（约三成、位置不重复），并写「任意两人不得同时满足同脸型＋同年龄＋同发型」。要扩到几十人就说「按矩阵换组合，制服不动」。
- 双人/三人组用**对照板**：上区并列（身高体宽差必须一眼可见）、中区每人四视图、下区几组局部对照（手/腰带/鞋）；负向词必列「两人同脸、双胞胎感、同一人两个角度、五官借用」。
- 群像服色与已有单人小厮/丫鬟必须拉开：家丁墨绿短打、门房小李子靛青、书齐茶褐、婆子深褐长褙子、粗壮婆子短褙子＋长裤＋绑腿（同制服的功能性变体，要在卡里标明“粗壮版差异三处”）。
- 年龄与身份的两头负向词都要堵：禁“少女化、双丫髻红头绳、珠翠金簪”（别画成丫鬟），也禁“老太太化、佝偻九十岁、缠小脚”（别画成衰败）。
- 分类：「群像」「对照板」都归 `人物·群像`（脚本按名字判定）。

## 交付格式（用户点名要求）
- **只要纯文本分段卡**：一张一区块、段落名保留（基础规格/画风锁/人物身份…/负向提示词），但去掉 `**` 与 `【】`；他想框选哪段就复哪段。
- 单卡请求（「我只要XX的」）→ 把该卡全文贴进代码块＋`MEDIA:单卡/*.txt`。
- 工具报「输入内容有误」→ 给**兼容版**：`导出兼容版.py <编号>`（整段压平、去星号、含 500–1200 字精简版）；典型成因是字数超限（1000/2000）与 `**`、`>`。

## 项目档案（萌娃心声）
- 路径 `~/duanju/萌娃心声/`：`剧集/EP001–EP059/图片提示词.md`（唯一真源，原稿缺第7集故跳号）、`输入/剧本/EPxxx.md`、`项目开发/资产总表.md`＋`资产登记_*.md`、`项目开发/文件规则.md`（画风锁/版式硬项/编号规则）。
- 四个派生脚本（均以剧集为唯一真源，禁止手改产物）：`重建汇总.py`（索引/总清单/xlsx/合集/分册/单卡）、`导出可复制合集.py`（纯文本分段卡→`全剧提示词-可复制版.txt`＋`可复制版/01–05`）、`导出兼容版.py`（报错时用）、`生成预览.py`（HTML，仅翻阅）。
- 现规模：59 集 / **209 张卡**（身份基准 33、状态变体 43、Q版 4、群像 8、场景 57、道具 64）。交付优先发 `单卡/*.txt` 与 `可复制版/`。
- `单卡/` 里既有 `.md`（原始骨架）也有 `.txt`（可复制版）——用户要能复制时发 txt。
