# 全季批量生产：波次配方与 QA 清单

适用：用户交整季（几十集）剧本，要求逐集产出 `剧集/EPxxx/图片提示词.md` 且格式与某集样板完全一致。

## 前置准备（主会话自己做，不派子代理）

1. **抽文本**：python-docx 按集标题正则切段，一集一个 `输入/剧本/EPxxx.md`（零填充三位）。检查集数连续性：跳号按原编号保留并明确告知用户，不重排。
2. **建总表** `项目开发/资产总表.md`，三部分缺一不可：
   - 样板集已有卡回填（编号/资产/类型/锁定要点一句话/主色 HEX 五值）——这是后续所有波次的造型真源；
   - 人物首次登场矩阵：对主角、配角、家族、地点关键词做「每集出现次数」扫描，输出 `集号(次数)` 序列；只提及 1–2 次的集常是话本/对话里带到，不算实际出场，以剧本实际描写为准；
   - 空的「新增资产登记区」，各波次追加。
3. **人物形态链**提前标注在总表（如：魂魄→胎儿→婴儿→满月→幼童），转变集必须出状态变体卡，变体卡写【基准锁定】段引用首次出卡编号。

## 波次划分

- **第 1 波（串行先行）**：登场最密集的引子集（主角团+主要配角基本在前几集全部登场），单独一批做完并登记完总表。后续波次的新人物定义以它为准，否则同一人物两张脸。
- **第 2+ 波（并行）**：每波最多 5 个子代理，每个负责连续 4–6 集；波内子代理的集区间不重叠。后波依赖前波登记碎片中的新人物（如男二在中间集登场、后面反复用），所以波与波之间要等登记合并完成。
- 每个**子代理**的指令必须包含：
  - 样板路径＋「逐字对齐骨架、分段标题、渲染尾，不凭记忆重写」；
  - 总表路径＋登记碎片命名规则（`项目开发/资产登记_EPxxx-yyy.md`），**每集完成即写**，不等批末；
  - 格式硬项清单（见下 QA）；
  - 冲突规则：依赖其他批次正在写的卡时，先做不依赖的集，最后回来；仍缺则自行定义并在汇报里标冲突风险；
  - 汇报要求结构化（每集路径/新卡数/沿用行数/自行设计可推翻的外貌决策）。

## 每集文件格式要点（与样板一致）

- 引言块口径句逐字沿用样板，仅依据行改指向 `剧集/<样板EP>/视觉设定.md` 与 `项目开发/资产总表.md`；
- `## 本集资产清单（N 张卡）`四列表；沿用资产行：原 IMG 编号＋类型列「T-XXX 沿用」＋不写正文段，表下加一行沿用口径注释；
- 新卡正文：`## IMG-EPxxx-Cxx/Lxx/Pxx · 名称` ＋ `- 参考：无外部参考` ＋ `### 可复制提示词`（每行 > 开头）；
- 人物/场景/道具三套分段标题逐字沿用样板；每集场景编号 SC001…按剧本自行分 3–5 场。

## 收尾 QA（主会话统一跑，子代理自报不算数）

对全部 `剧集/EPxxx/图片提示词.md` 逐文件检查：
1. 渲染尾逐字出现（含全角逗号）且在每个【负向提示词】段尾；
2. 人物身份卡含 AI演员声明整句；
3. 每卡 HEX 色板 5 色；
4. 同文件内 IMG 编号无重复；同一资产全剧身份卡编号唯一（grep 全季验证）；
5. 清单表标「沿用」的行在文件内无正文段；
6. 文件数＝剧本集数（跳号除外）。

grep/正则可机械验证的项全部用脚本验，不过目测；发现缺失回补后再验一次。

规则落在 `scripts/qa_markdown_cards.py`：直接跑，不要每批手写一遍正则。它同时报「清单表头张数≠表行数」「同一卡名在多集都写了正文」两类跨集问题——手写脚本只看单文件，这两类从来抓不到。

## 波次结束后的合并与去重（主会话做）

1. **合并登记**：把 `资产登记_EPxxx-yyy.md` 追加进总表「新增资产登记区」，碎片文件保留作追溯。
2. **跨集重复检查**：同一地理/道具被两波各出一张卡（并行波几乎必有）。保留先落盘的编号，另一集撤卡改「沿用」，同时改它的清单表行编号，并加一行对账注记写明原误出编号与撤卡原因。
3. **冲突裁决写进总表**：形态链终版顺序、同一人物的多张变体各自使用区间、同名不同址的地点（如两处庄子，负向词互斥）、重复道具、以及「先落盘为准」的编号归属，集中记在总表的「跨批次对账裁决」小节。
4. **缺集补齐**：按「剧本集数 = 文件数」对账；缺的那集由主会话自己写（读该集剧本、对齐相邻集骨架），不要重派同一个子代理——重派会用同一份上下文再撞一次。

## 交付包

- `图片提示词索引.md`：表格（集/标题/本集新卡正文数/清单行数/文件路径），让用户一眼看全季进度与缺口。
- `zip -qr` 打包 `剧集/`、`项目开发/`、索引，放到 `~/Downloads/`，同一条回复给 MEDIA 卡片。
- 汇报必须带三件：缺集情况、自行设计（可推翻）的外貌决策、主会话手写补齐或撤卡的集号。用户要的是「哪里还能改」，不是完成宣言。

## 第二阶段：去重汇总（用户交付后几乎必问）

逐集文件交完，用户下一句通常是「汇总成一张表，人物和场景别重复出现，让我知道总共要生多少张」和「能不能直接整理在一起，别让我回每集去翻」。第一阶段就一次给齐这三件产物，省一轮往返：

1. **`全剧资产总清单.md`**：去重后每张卡一行（编号｜名称｜首出集｜引用集数｜用于（集）｜锁定要点），顶部一张统计表（身份基准 / 状态变体 / Q版 / 场景 / 道具 / 合计），末尾给生成顺序建议。
2. **`全剧生成清单.xlsx`**：汇总表 + 五张分表（人物基准 / 变体 / Q版 / 场景 / 道具，带筛选与空的「已生成√」列）+ 按集进度表。用户要能边生边勾，不是只看一眼。
3. **`全剧提示词合集-去重版.md` / `.docx` + `合集分册/01…05`**：每张卡的**完整可复制正文**按类排在同一个文件里，开头目录表可跳转；分册按类拆（人物基准 / 变体 / Q版 / 场景 / 道具），用户在做哪块就开哪个文件。**只给索引＝把检索工作推回用户**，一定要带正文。

解析与统计的坑：

- **引用集数按「该 ID 在文件任意位置出现」统计**（含变体卡的【基准锁定】引用），只数清单表行会让身份基准卡显示「只用于 1 集」，与实际严重不符。
- **锁定要点要切掉 HEX 尾巴**：`re.split(r'[；。]\s*(?:HEX|视觉单元|色板|色板取样)', note)[0]`，否则整列变成一片 `#RRGGBB`。
- **「首出集」按编号里的 EP 号回填**，不要用「第一次在哪个文件出现」——沿用行会把它提前。
- **去重体检两项必做**：①悬空引用（清单行引用的编号全季没有任何卡正文，多因并行波里另一波改了编号）；②卡名归一化后重名（剥掉 `地点板|道具板|身份板|形态板|状态板|造型板|对照板` 再比）。两项都干净才算去重完成。
- 优先级分档：身份基准与场景 = A 必生；引用 ≥4 集 = B 高频；2–3 集 = C；单集 = D。
- 生成顺序固定这样写：先「地基约 10 张」（主角团身份基准 + 主要府邸正厅/外景）→ 场景全量一次定死（场景返工代价最高）→ 其余身份基准随集推进 → 变体/Q版/道具跟分镜走。
- 合集与分册按 `\n---\n\n# ` 切分；卡片正文里不要出现裸 `---` 行，否则切分会断。

机械部分直接跑 `scripts/build_asset_aggregate.py <项目根目录>`，它产出上述三件产物并打印去重体检结果。

## 小坑

- bash 循环里别写 `"$d图片提示词.md"`：变量名与中文相邻会被当成一个变量名，循环静默不输出；用 `"${d}/图片提示词.md"`。
- 渲染尾在每份文件的引言块里也出现一次（口径说明），校验必须按「每个卡正文段内」计数，按全文计会多算法。
- 子代理汇报的「已全部自查通过」只能当线索：它的正则常把自己的引言行算进去而误报，也会漏掉跨集问题。以主会话跑脚本的结果为准。
