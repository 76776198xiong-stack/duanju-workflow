# 短剧资产图片提示词

把视觉事实写成可复用、可修改、可直接复制的角色板、场景板、道具板或状态图提示词，统一保存到
`剧集/<EP>/图片提示词.md`。每项用 `IMG-...` 标题，正文放在 `### 可复制提示词` 引用块。
`IMG-...` 是提示词条目的稳定 ID；实际图片须由创作者提供，或来自经确认的生产结果。

每项使用 `## IMG-... · 中文名`，写一行不加粗的 `- 参考：`。无外部参考时写 `- 参考：无外部参考`；
有真实图片时使用 `REF-<slot>（顺序：<n>）· <项目相对路径>《<中文名称>》（用途：<用途>；控制：<范围>；不得控制：<范围>）`。
多张用 `；` 连接，顺序从 1 连续编号；正文标题固定为 `### 可复制提示词`，每个非空正文行以 `>` 开头。
`REF-...` 指向当前项目中的真实图片；下游分镜的 `PLAN-...` 挂图计划不能证明本条图片提示词已有参考输入。

## Quick Start

```text
用 $short-drama-image-prompts 为 EP001 已确定的人物、地点和道具写可直接复制的图片提示词
```

## 入口

有当前视觉设定即可直接开始；剧本只在提示词需要确认剧情状态时读取。Look Development 是可选分支。
先确认用途：身份板、造型/状态变体、地点板、道具板、组合 production sheet 或比较风格帧。
分镜需要生产尾帧时，可把已接受的「收尾关键帧提示词」落实为独立 `IMG-...` 状态图条目：
说明来源 SHOT 与终点，沿用视觉事实和参考范围，不重新设计动作。实际生成以该 IMG 条目为来源。

创作者可读说明跟随项目语言；可复制正文跟随 `short-drama.json#/format/prompt_language`。没有
`short-drama.json` 时正文默认
使用 `en`，并在同一任务中保持一致；不能从创作者说明语言推断提示词语言。

**创作者说「格式按 <另一个项目>」时**：先读那个项目的 `剧集/<EP>/图片提示词.md` 和它的 `项目开发/文件规则.md`，把对方的卡式骨架、分段标题、渲染尾逐字沿用，不要凭记忆重写。切口径要同时改三处，缺一处下游就打架：

1. `short-drama.json#/format/prompt_language`（en ↔ zh-CN；切 zh-CN 后关键帧正文语言随之变）；
2. `项目开发/文件规则.md` 里那条口径裁决行（写明依据与日期，下文 §口径二选一要求不许混写）；
3. 删掉并存的旧口径文件（例如先写过英文短提示词草稿，就删它，不要让两套并存）。

改完重跑 `project_card.py`，并说明语言切换对下游关键帧的影响。

## 工作流

1. 锁定这一张图要固定的身份、状态、空间或比较变量。
2. 只读所需资产事实、视觉方向、负面约束和已提供参考图。
3. 按“主体与身份锚点 → 当前变体 → 构图/视角 → 光色/材质 → 背景边界 → 禁止项”写正文。
4. 每张参考只控制已声明的范围，并在 `REF-...` 槽位里写出封闭词表中的 `用途`；具体范围见[通用配方](references/common-recipe.md)。
5. 检查身份与变体、文字政策、视角和光线是否冲突。
6. 用户要全部资产就完成全部，资产组只是内部批次。

## 提示词要求

- 开头先写对象和用途，不用风格词淹没身份。
- 只包含当前图能同时满足的要求；多视图/状态对照写清版面关系。
- 保留稳定识别锚点，变体只改允许变化的部分。
- 被《视觉设定.md》连续性锁点名的条目，锁面原样出现在可复制正文里，让这张参考图本身就把跨镜事实定住。
- 避免无验证作用的质量词堆砌。
- 可见文字、logo、水印、界面和字幕明确允许或禁止。
- 正文可直接复制，不含占位符、流程说明、文件路径或 QA 结论。

## 全季批量生产（几十集一次交付）

用户交整季剧本、要求「每集一份、格式与某集样板一致」时走批次模式，不要一集一集硬写：

1. 主会话先铺三件基础设施再派活：按集标题切出 `输入/剧本/EPxxx.md`（三位补零）、建 `项目开发/资产总表.md`（样板集已有卡回填＋人物首次登场矩阵＋人物形态链）、锁定样板集路径。剧本缺集跳号按原编号保留并先告知用户，不重排。
2. 资产总表是全季唯一造型真源：后续任何批次都据它判断「新卡 vs 沿用」。剧本没写死的外貌自行设计并在总表标「可推翻」——用户改一个词，全剧跟着变。
3. 沿用的卡不重出正文：清单表保留原 `IMG-...` 编号、类型列写 `T-XXX 沿用`、表下加一行沿用口径注释。这样每集文件自足、格式统一，又不会把同一张脸写两遍写出差异。
4. 波次：引子集（主角团与主要配角登场集）单独串行做完并合并登记；之后并行，每波≤5 个子代理、每个 4–6 连续集、区间不重叠。波与波之间先合并登记再发下一波，否则同一人物会被两波各写一张脸。
5. **子代理自报不算数**：每波结束由主会话自己跑 `scripts/qa_markdown_cards.py`，缺集与重复卡的裁决权也在主会话。
6. 交付 = `图片提示词索引.md`（集号/标题/新卡数/清单行数/路径）＋整包 zip 到 `~/Downloads/` ＋ MEDIA 卡片 ＋ 目录树。用户会直接问「文件在哪」，别等他问。
7. 接着给**去重汇总**：全剧总清单（一行一张图）＋可勾选 xlsx ＋把每张卡的完整正文排在一起的合集（按类分册）。用户接着必问「总共要生多少张」「能不能直接整理在一起」——汇总必须自带正文，只给索引等于让他回各集翻。详见 references/series-batch-production.md。

关键坑：
- 并行波必然出现**同一地理被两波各出一张地点卡**：合并时做跨集重复检查，保留先落盘的编号，另一集撤卡改沿用，同时改清单行编号并加对账注记。
- 并行波常有 1–2 集因限额或失败没落盘：主会话按文件数对账后**自己补齐缺集**（读该集剧本＋相邻集文件对齐骨架），不要原样重派同一个子代理。
- 形态链跟剧本时间线对齐：台词里的年龄说法（「才两岁多点」）不推翻视觉链，以总表形态链为准并在集内注明口径出入。
- 剧本标题与正文不符时以正文为准（标题写「关门放狗」而正文无狗，就不出狗卡）。

## 完成与投产

每个点名对象都有明确用途、可复制正文、参考边界和禁止项，且相互不矛盾，即完成。本次请求同时
修改图片提示词与分镜时，当轮刷新受影响镜头的「图片提示词项」，不另建对账产物。实际生成必须
转 `$short-drama-produce`，展示精确任务并取得显式确认；本技能不调用外部服务。
五份创作文档齐备后，可转 `$short-drama` 对跨文档结构做一次机械核对；内容质量仍由创作者审查。
