# 短剧剧本 → 全剧图片提示词库 · 完整工作流

> 这是一套**与具体剧本无关**的生产流程：输入任意一部短剧/漫剧剧本（docx 或 md），产出一座「全剧去重、跨集一致、可直接复制出图」的图片提示词资产库。
> 本流程在《萌娃心声》59 集（215 张卡）上完整跑通并多轮返工验证；该项目的具体内容不在本仓库，本仓库只沉淀**方法、技能与工具**。
> 面向读者：接手的智能体（AI agent）或人类协作者。

---

## 〇、总览：从剧本到交付的六步

```
docx 剧本 ──①切集──▶ 分集 md ──②资产盘点──▶ 人物/场景/道具清单
      ──③分波出卡──▶ 剧集/EPxxx/图片提示词.md（唯一真源）
      ──④登记合并──▶ 资产总表.md（跨集一致性）
      ──⑤三层校验──▶ 格式/悬空编号/重复卡
      ──⑥一键派生──▶ 可复制版/兼容版/xlsx 清单/HTML 预览/索引
```

核心思想只有三条：
1. **唯一真源**：所有卡正文只存在 `剧集/EPxxx/图片提示词.md`，其余全是脚本派生，禁止手改。
2. **一物一卡**：同一资产全剧只出一次卡，后续集「沿用」不重出；变体（换装/年龄/状态）另出卡并【基准锁定】引用首卡。
3. **一致性靠登记不靠记忆**：每张卡的锁定要点＋HEX 登记进资产总表，跨批次的人只读总表就能对齐。

## 一、项目初始化

```
项目根/
├── 剧集/EP001…/图片提示词.md      ← 唯一真源
├── 输入/剧本/EP001….md            ← 切好的分集剧本（原文，永不修改）
├── 输入/参考图/                    ← 用户成图，卡头用 REF-xx 绑定
└── 项目开发/                      ← 资产总表、登记碎片、文件规则、脚本
```

1. docx 用 python-docx 按 `^第\s*\d+\s*集` 正则切分（**原稿可能缺集跳号，照原样保留**；夹在两集之间的"无名段"可补录为独立 EP 编号）。
2. 建空的 `资产总表.md`：先放「人物首次登场矩阵」（用关键词 grep 各集剧本统计人名出现集数，人工核定首出集）。
3. 写一份 EP001 样板卡（或指定已有通过版做样板），**后续所有卡的骨架逐字对齐它**。
4. 把硬规则写成 `文件规则.md`（见第三节），改口径先改规则再改卡。

## 二、卡格式规范（硬规则，缺一不可）

**人物卡十段**：基础规格与全局构图 → **画风锁** →（变体卡：【基准锁定】/【面部锁定】）→ 人物身份与性格 → 外貌与服装设计补充 → 左侧区域 → 中间区域：完整全身四视图 → 右侧区域（3 表情+头部细节+色板）→ 底部区域（2 动态+4 局部+线稿+比例尺）→ 文字与版式 → 负向提示词 → 图外标注（不进提示词）。

**场景/道具卡五段**：全局规格与画幅 → 画风锁 → 本体锁定 → 版式排布 → 负向提示词 → 图外标注。

1. **画风锁（每卡必带、最高优先级）**：`必须是 3D 动画 CG，不得出现真人质感`＋CG 亚光皮肤（无毛孔/汗毛/油光颗粒）＋渲染光斑＋发丝成束＋干净折面＋禁真人/实拍/剧照/写真/photo-real。渲染尾全剧逐字统一（本项目用 `3D Chinese animation style，semi-realistic，high-end CG，studio lighting，soft film grain。` 全角逗号——它是画风识别码，**一字不改**，改了新旧图就接不上）。
2. **负向词固定前缀**（防真人质感）：`真人，实拍照片，photorealistic，photo-real，电影剧照，影视剧照，影楼写真，cosplay 真人，真人演员，皮肤毛孔可见，汗毛，油光颗粒，实拍皮肤纹理，真实摄影反光`＋该卡专属负向。**负向词里禁止括号注释**（会被一起复制进出图工具）。
3. 人物卡右下角 AI 演员声明整句；HEX 色板 5 色只写数值；16:9/4K；正文每行 `>` 开头放 `### 可复制提示词` 引用块。
4. **四视图铁律**：同一 3D 模型旋转观察，左右侧面严格反向、背面严格背对、不裁切；负向必带「四视图造型变化、四视图换人、两个侧面朝向相同、缺少背面」。
5. **编号**：`IMG-EPxxx-Cxx/Lxx/Pxx`（C 人物/L 地点/P 道具，集内 01 递增）；多人对照板/群像归「人物·群像」。
6. **每集文件**＝引言块＋`## 本集资产清单（N 张卡）`四列表（编号/卡名/类型/用在哪些场）＋新卡正文；沿用行类型写 `T-XXX 沿用`、**不写正文**；表下注「本集不出卡」名单（路人/一次性角色走剪影）。
7. **可见文字**：能不写就不写；必须写的（书名/匾额/腰牌/榜文）单列「逐字正确」，其余「字迹虚化不可辨」。

## 三、跨集一致性三件套

1. **【基准锁定】**（状态变体卡必写）：引用首出卡编号，逐条列「本状态差异」，只改允许变的部分。
2. **【面部锁定（逐项复刻）】**（脸走形风险高时加）：脸型与下巴收势、三庭比例、眉（峰位/眉尾走向）、眼（内外眼角方向、眼裂长宽比、双眼皮折线、卧蚕、瞳色）、鼻（山根/鼻头/鼻翼）、唇（厚薄/唇峰/**笑意特征**）、痣（毫米、位置、形状）、年龄感；末尾铁律「四视图+表情+动态同一张脸；不得为更好看放大眼/削下巴/抬鼻梁/改唇形；**宁可重出，不许换脸**」。
3. **资产总表**：一行一资产（编号/名称/类型/锁定要点/5 HEX）＋跨批次对账裁决（形态链、同址多态、撞装区分）。改卡必同步总表。

## 四、批量生产（多智能体分波调度）

1. **第一波只派 1 个子代理**做开篇 4–5 集：定下主要人物基准卡＋写登记碎片——它是后续所有波的锚。
2. 之后每波 ≤5 个子代理并行，每个吃 4–6 集。子代理任务书必含：格式样板路径、资产总表路径、剧本路径、输出路径、登记碎片路径、冲突处理规则。
3. **并行冲突规则**：需要的卡若属于其他波正在写的集→先做别的、最后回来轮询；始终未落盘→自行定义并在汇报标「冲突风险」；合并时按「同一地理一张卡」撤重复卡、改沿用、留对账注记。
4. **子代理撞 API 限额（429）整批失败**→主控自己补写缺口集；**用磁盘文件数×格式校验确认"真的写完"，不信汇报**。
5. 每波结束：把登记碎片并入总表，下一波才有真源可读。

## 五、三层校验（每波收尾必跑，脚本化）

1. 单卡：渲染尾恰好 1 处、负向段存在、C 卡有 AI 声明/L·P 卡无、编号无重复、无外集编号、沿用行无正文。
2. 全库：悬空编号（引用了不存在的卡）、同名近似卡查重（济安堂/御花园类重复要撤）。
3. 清单：表头张数=表行数；每集行数参考 6–14 行，**主线人物扎堆的开篇集可到 17–19 行，不硬限**；索引重建。

## 六、派生与交付（改卡后必跑）

```bash
python3 项目开发/重建汇总.py        # 索引/总清单/xlsx/合集/分册（读剧集/重建一切）
python3 项目开发/导出可复制合集.py   # 纯文本分段卡（用户日常出图用，框选即复制）
python3 项目开发/生成预览.py        # HTML 搜索预览（可选）
python3 项目开发/导出兼容版.py --all  # 每卡纯文本版＋精简版（511–1181 字，防工具字数超限）
```

（`tools/` 里是这四个脚本的可用实现：复制进新项目的 `项目开发/` 目录，把每个脚本顶部的 `PROJECT_NAME` 改成新项目名即可复用；详见 `tools/使用说明.md`。）

**交付物矩阵**：日常出图→`可复制版/`＋`单卡/`；工具报错→`出图兼容版/*_精简.txt`；盘点勾进度→xlsx；检索→HTML 预览；改卡→只改 `剧集/`。**给用户交付时：聊天里贴全文＋单卡文件，并附一张要点表**（他英文/AI 术语看不懂，用大白话＋表格）。

## 七、单卡返工 SOP（用户看完出图后点名改，最高频）

| 用户说 | 实际要做 |
|---|---|
| "太丑/不好看" | 换**轮廓**不是换色：裙型（百迭→马面→齐胸）、发型结构、层次；旧款写进负向词 |
| "只换颜色" | 改 HEX＋色名，负向加旧色名；**连带 grep 所有"沿用制式"的变体卡与总表一起换** |
| "脸变了！" | 强化【面部锁定】；**根治靠图生图**（见下） |
| "要 XX 背景板" | 无人物空镜四格＋合成站位＋整洁铁律（见第八节） |
| "几十名 XX" | 群像卡：制服统一＋差异矩阵（见第八节） |
| 工具报"输入内容有误" | 字数超限或 Markdown 星号→给兼容版/精简版 |

**保脸的图生图换装法（整张重画必换脸，这是铁律）**：
1. 用户成图存 `输入/参考图/`，卡头绑 `REF-01（顺序：1）· 路径《名》（用途：面部与发式基准；控制：脸型五官痣发式骨架；不得控制：服装孕态）`。
2. 卡末附「图生图·换装指令」小节：底图＋【保持不动】清单（脸/痣/发式/簪坠/骨架/镜头/版式）＋【只改三处】清单＋负向。
3. 操作参数：走图生图/局部重绘，**蒙版只涂要改的区域**（腹部/衣裙），脸不涂；重绘强度 0.3–0.45；一次只改一类（先改色、再改肚子），多改并举必然重画整个人。
4. 没有蒙版的工具分两步跑，先色后形。

## 八、两类高频卡的专项规范

**背景板（空镜合成用）**
- 定义：无人物四格场景卡，正文写明"供分镜直接合成人物与手持道具"；负向加"人物入画/主角特写/手部入画"。
- 锚点 5–7 件缺一不可；**必写合成站位**（主位/客位各用哪张人物卡）。
- **整洁要列成铁律**（被褥方正叠床尾、枕头并排、帐幔对称挂起、箱盖合齐、**地毯上必须空无一物**、桌面只留茶具），负向枚举凌乱物件——否则模型一定加戏成凌乱。
- 光两头堵：中高明度＋主光方位四格一致＋禁夜景/烛光/压死；要暗也写"暗部提亮到 15% 灰、细节可见"。
- 空间关系显式化：同府不同房间列「与 XX 为不同空间不得混用」；同址两态（完好/毁、常日/搜检）出两张卡注明对切。

**群像卡（T-GRP）**
- 一张卡覆盖一支队伍：**制服 5–6 项一字不差**＋**差异化矩阵**（脸型×年龄×眉眼×印记，任意两人不得"同脸型+同年龄+同发型"）＋版式（主区 N 人阵列/右侧面孔格/下区队形示意＋局部）。
- 双人对照板循先例：两人各自四视图＋负向「同脸、同一人两个角度、五官借用、撞装」。
- 负向必带：同一张脸复制粘贴、克隆人、制服不统一、身份串味（丫鬟变小姐、家丁变侍卫盔甲佩刀）。

## 九、方法论沉淀（让画面自己讲故事）

1. **材质区分阶层**：豪门=紫檀+鎏金+青瓷+暖光高明度；寒门撑体面=酸枝+素铜不鎏金+青花+偏冷低一档色温+三处"半旧"硬细节（磨痕/氧化暗斑/踩踏磨亮）；皇家=汉白玉+琉璃+硬光长影。同一府邸不同房间互为冷暖对照，写进卡里。
2. **气质写成可画的四要素**：如"善良"=眉尾垂+眼尾平+嘴角天生上翘+体态是"让/递"；"精明"=吊眼+薄唇+皮笑肉不笑。形容词一律翻译成五官与体态。
3. **只换颜色用户会觉得没改**；款式/轮廓/结构变了才算改。
4. **年龄链管理**：主角从婴儿→学步→幼童→成人的每个形态一张变体卡，总表记"形态链"，分镜按剧本年龄对号。
5. **白系服装**：暖白/冷白/银灰分层防糊成一块；负向禁丧服/孝服/病号服/睡袍。
6. **植物类细节**（金桂/落花）写"细碎小金点"并负向"画成树叶/色块"。

## 十、在新剧本上复用的步骤清单

1. 建骨架（第一节）→ 2. 切剧本 → 3. grep 人名做登场矩阵 → 4. 写 EP001 样板卡＋文件规则 → 5. 第一波单子代理出开篇基准 → 6. 分波并行＋登记合并 → 7. 三层校验 → 8. 一键派生 → 9. 按第七节返工循环 → 10. 交付矩阵发货。
预计量级参考：59 集 ≈ 215 张卡 ≈ 数小时（5 并发）。

## 十一、常见坑（都是真实踩过的）

出图工具字数超限/星号报错→兼容版；HTML 复制按钮被剪贴板权限挡→主交付用纯文本；负向词括号注释污染；四视图换脸；表情格改了眼裂形状；只换色不算改款；金桂画成黄叶；白衣画成孝服；并行撞重复地点卡；json.dumps 前 set 转 list；heredoc 贴长中文可能带 BOM→先 write_file 再拼；子代理 429→主控补写；信磁盘校验不信汇报。
