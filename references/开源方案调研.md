# 开源方案调研（初筛）

日期：2026-11-13。目的：选一套开源方案作为流水线的基础，不限于 drama-skills。

**说明**：以下信息来自各项目的 README、两份开源工具汇总清单，以及 drama-skills 维护者写的一份对比（他们自己也在对比之列）。都是项目自述，**没有一个实际安装运行过**。星标数是查看时的数字。

## 两类方案

- **A 类：Agent 技能包。** 装进 Codex 或 Claude Code，没有自己的界面或只有简单看板，产物是文件夹里的文件。
- **B 类：自带界面的工作台。** 桌面应用或自己部署的网页应用，界面、流程、模型接入都做好了。

我们原来的设想是"A 类流水线 + 自己做一个薄的监控界面"。但 B 类里已经有带画布、带 Agent 的现成工作台，也值得评估。

|---|---|---|---|---|

## 和我们的需求对照

| 我们的需求 | 要看什么 |
|---|---|
| 朋友不再复制粘贴、开新对话 | 所有候选都能解决 |
| 定好剧本后，文字到出图全自动 | 能否无人值守连续跑完；有没有强制的人工确认步骤 |
| 人只审图、审成片 | 有没有看图、选图、打回重做的界面 |
| 不再手动链接图片和人物名称 | 能否通过接口直接调 Seedance 2.0，并自动把参考图带上 |
| 能继承朋友的资产规则（十段人物卡、3D 画风锁等） | 提示词规则能不能改、好不好改 |
| 以后能卖给别人 | 许可证：MIT / Apache-2.0 可以；Elastic 2.0 有限制；CC 非商用不行 |
| 工作台不要复杂，只做监控和审核 | A 类要自己补界面；B 类界面现成但可能过重 |

## 建议的评估办法

读文档选不出"最好用"的，要上手试。

1. 先按许可证筛掉不能商用的（火宝、ai-anime-series）。
2. 入围三个：**drama-skills**（A 类里最全）、**Toonflow**（B 类里最热门且 MIT）、**shuohao-skills 或 Dramake**（A 类的第二选择）。
3. 用同一份材料各跑一遍：《萌娃心声》第一集，2 到 3 个人物加前 5 到 8 个镜头，到出图为止。
4. 记录：装起来花了多久、中途人要操作几次、出图质量（朋友看图判断）、提示词规则好不好改。
5. 按结果定基础方案。
