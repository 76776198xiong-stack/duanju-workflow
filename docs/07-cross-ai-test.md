# 给另一位 AI：执行第一集资产出图测试

这是一个实际执行任务：按本仓库保存的朋友工作流，把给定第一集剧本做成资产提示词和资产图。先生成洛洛1张完整资产设定卡，展示给负责人，等看图通过后再做其余资产。

本次所需的剧本、工作流、技能、模板和检查脚本都在本仓库。直接开始工作，不再向负责人索要本地资料。

## 任务范围与最新决定

- 输入是已经分好的第一集，不重新分集、不读取或续写其他集。
- 使用朋友的 GitHub 资产工作流；不要换用原版 drama-skills，也不要自行改良模板。
- 负责人只审图片。你负责资产盘点、设计补全、提示词、登记、检查和出图；不让负责人审中间文字，不反复询问“是否开始”。关键冲突确实无法按规则裁定时，集中说明。
- 没有现成洛洛定稿图。不要把缺少定稿图当成停点；按朋友规则处理剧本没写死的外貌，登记为可推翻的设计补全。不要读取其他 AI 的成图或测试项目来补设定。
- 本次不查找故事板样例，不涉及七海画布、安装包或软件资源。
- 本入口覆盖资产环节；视频提示词、视频、Updream绑定不在本任务内。镜头表与分镜草图的后续任务另行交接，不在这里猜测缺失规则。
- 仓库旧的第一轮/第二轮过程文档是历史背景；本入口描述的是负责人为另一位AI新授权的独立执行，不需创建Codex对话或接手其他人的运行目录。

## 实际执行顺序

1. **读取剧本并盘点**：明确第一集实际入画的人物、地点、道具与状态变体。区分现场人物和只被台词提及的角色，按朋友规则决定新卡/沿用/不出卡。已经分好的第一集不再切集。
2. **建立独立输出目录**：输入原文只读；按朋友工作流建立`输入/剧本/EP001.md`、`剧集/EP001/图片提示词.md`和`项目开发/资产总表.md`等文件。不要覆盖别人的测试。
3. **先完成洛洛基准卡**：严格按模板编写完整人物资产提示词，登记身份锚点、造型、五色HEX，以及剧本未明确而自行设计的决定。初始常态和炸炉后/Q版魂魄分开，不把不同时间状态混成一人。
4. **执行检查**：运行下面的原脚本，并核对本阶段适用的模板要求。文字中的可修正错误由你修正。只做了单卡时，清单数量要与已落盘卡匹配，其他待做项在盘点中标明；不伪造整集已完成。
5. **生成洛洛1张**：使用该卡的可复制提示词，排除图外标注，调用你当前环境实际可用的生图能力。要求是整张16:9横向设定卡，不是单视角人物立绘。目标4K；工具不支持时用可用的最大原生尺寸，记录实际像素，不用插值放大冒充原生4K。允许不同AI使用不同生图模型，但必须记录名称和方式。不要未经授权新增付费API订阅或索取密钥。
6. **查看并展示**：实际查看结果，记录缺模块、错字、四视图不一致等具体问题，注明是自检；保留原图并直接向负责人展示。此处停下，等待负责人看图采用或要求修改，不提前批量生成其余资产。
7. **洛洛通过后继续**：以采用图及其卡为基准，按朋友规则补齐第一集其余资产，处理沿用/变体引用、登记及派生交付。按依赖拆小批次，逐张检查并保存；负责人分批看图。需要参考图时实际传图，不用文字声称绑定代替真实输入。

如果你的环境没有生图工具：完成能执行的提示词与检查，并如实说明缺少生图能力；不拿SVG、HTML、示意占位图当作生成结果，也不宣称已出图。

## 可直接用的检查命令

在仓库根执行，最后一个参数换成你自己的独立测试目录：

```bash
python3 references/upstream/duanju-script-to-prompts-workflow/skills/short-drama-image-prompts/scripts/qa_markdown_cards.py /path/to/your-test-project
```

脚本通过只能证明它检查到的机械项。需要同时实际看图；看不到图片的区域或细节不要写“通过”。本次只做单集，不启动多集并发。

## 给负责人看的输出

第一次交付只需要：

1. 洛洛完整资产设定卡图片。
2. 一两句实际发现的问题；没有明显问题也直接说。
3. 实际生图模型/工具、像素尺寸和原图位置。

完整提示词、设计补全、检查输出、参考绑定、用时和失败/修改记录自行保存，方便追查。人不需要读这些文字才能继续审图。

比较由负责人看图决定：版式是否完整、四视图是不是同一个人、发饰腰包等细节是否一致、中文有没有错字、画风和精细度是否符合预期。具体脸型与服色允许不同，不以和另一个AI长得一样作为通过条件。
