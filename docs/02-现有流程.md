## 外部仓库提供的经验

[外部工作流仓库](../references/README.md#公开参考仓库)描述的链路为：分集文本 → 资产盘点 → 分批出卡 → 登记合并 → 机械校验 → 派生交付。

有价值的候选做法包括：

- 同一资产只定义一次，后续集沿用；换装、年龄或状态差异引用基准卡。
- 正文集中维护，索引、可复制版和预览由脚本派生，减少人工维护多份文本。
- 批次之间合并登记，处理同名地点、缺卡与重复编号。
- 为返工区分保留项与允许变化项，并记录参考图的控制范围。

这是对参考方法的归纳，不代表本项目已经采用其全部规则。外部技能明确把实际生成放在其他阶段，其提示词产出不能等同于已生成图片。

## 材料中尚未解决的口径差异

| 差异 | 当前处理 |
|---|---|
| 早期资料提到 Seedance 2.0，部分包标记 SD2.5 | 保留原标记；实际平台与版本在测试配置中记录，不能从名称推定可用能力 |
| 不同规则使用15秒或30秒容器 | 不带入首轮静态图片测试；后续视频任务再决定 |
| 规则要求禁止文字，剧情又需要书名、匾额或界面文字 | 单独列明需要可读与不需要可读的文字，不用一条全局禁令覆盖 |
| 人物资产模板允许补设计，部分剧本保真规则禁止额外设定 | 将补充设计标为待确认，不混入原文明示事实 |
| 人物模板默认成人比例，本剧含萌娃与非人角色 | 按原文形态处理，不机械套用成人头身和站姿 |

## 候选技术方向

分集隔离、持久化资产库、主流程调度和结构化任务记录是早期提出的方案。它们可以减少重复提供上下文，但不能保证视觉绝对一致。浏览器自动化、平台 API 或现成画布工具的取舍，都需根据真实接口和一次完整任务再决定。

相关缺口及验证动作见[问题台账](03-问题台账.md)。
