# 00 术语

状态：提议稿。朋友压缩包里的叫法等 Codex 清点后补进来，再定最终用词。

## 两层东西，不要混

**成品提示词**：直接交给生图或视频模型的文字。

**工作提示词**：交给文字模型、让它写出成品提示词的那份指令。每一种成品提示词背后都有一份对应的工作提示词。

| 成品提示词（给生图/视频模型） | 它依赖的工作提示词（给文字模型） |
|---|---|
| 资产提示词：生成人物、群像、场景、道具图 | 资产工作提示词 |
| 分镜提示词：生成每个镜头的分镜图 | 分镜工作提示词 |
| 视频提示词：在 Updream 里生成视频 | 视频工作提示词 |
| （无） | 审查提示词：让 AI 检查并修改上面的成品提示词。它也是一份工作提示词 |

## 各方现在的叫法

| 概念 | 负责人 | 朋友的 GitHub 仓库 | 朋友的压缩包 |
|---|---|---|---|
| 给文字模型的指令 | 工作提示词 | 技能（Skill）。技能下面的细则叫"配方""模板""规则"，示范用的那张卡叫"样板" | “便携系统提示词”“一键启动提示词”“当前有效总规则”；各目录规则也叫“Skill” |
| 资产提示词 | 资产提示词 | 图片提示词；一条叫一张"卡" | “人物提示词”“场景提示词”“群像提示词”“道具提示词”；Word称“Midjourney提示词” |
| 分镜提示词 | 分镜提示词 | 仓库里没有这一段，只提到"关键帧"。在它所属的开源套件 drama-skills 里，分镜图叫"冻结关键帧"，分镜提示词叫"关键帧提示词"，一个镜头的编号是 `SHOT-...` | “分镜大纲”“正式分镜”“Markdown分镜”；现有命名主要指镜头表，未见独立静态生图提示词命名 |
| 视频提示词 | 视频提示词 | 仓库里没有 | Word模板名“即梦多镜一体化容器提示词”；打斗Word名“高燃打斗视频提示词” |

朋友的仓库里没有出现"工作提示词"这个词。

## 提议

1. **两层的区分保留**，文档里始终分清"成品提示词"和"工作提示词"。
2. **"工作提示词"和"Skill"是同一个东西的两种形态。** 贴进 Gemini 网页对话的那段文字叫工作提示词；搬到本地 Agent 后，它就是一个 Skill。讲朋友现在的流程时用"工作提示词"，讲新系统时用"Skill"。
3. **"分镜提示词"专指生成分镜图用的提示词**，不包括视频提示词。朋友仓库里的"关键帧"是不是同一个意思，要问他。
4. **资产提示词不叫"卡"**。"卡"在朋友仓库里既指提示词条目，也指生成出来的那张设定图，容易混。文字叫"资产提示词"，图叫"资产图"。
