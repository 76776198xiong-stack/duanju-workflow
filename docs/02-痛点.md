# 02 痛点

分两部分：他自己说的，和我们分析出来的。后者是推断，需要拿真实的一集来验证。

## 他自己提出的

### 1. 没有一体化工作台

剧本、提示词、资产图、分镜图、视频提示词散落在多个 Gemini 对话和即梦网站里，最后要手动汇总。同行已经有人在做一体化工作台，他也想要一个。

### 2. 每一步都要手动复制、新开对话

用的是 Gemini 网页版，步骤之间没有任何衔接。每产出一份文字，都要复制出来，新开对话，重新喂工作提示词，再贴进去。一集要重复很多次，59 集就是几百次。

### 3. 提示词质量不稳定，只能靠人工加一道审查

没有控制好一集的文本量时，工作提示词产出的资产提示词会变得模糊、失效，最后生成的图片素材效果差。分镜提示词同理。

他现在的补救办法是加一道审查：新开对话，喂审查提示词，把产出贴进去审，改完再拿去生图。这道审查有效，但又多出一轮复制粘贴，人工成本很高。

### 4. 即梦里的手动绑定

资产图、分镜图、视频提示词要一条条手动上传，并手动建立"哪段文字对应哪些图"的关系。

## 我们分析出的

### A. 问题 2 和问题 3 是同一个根源

网页对话没有"固定输入"的概念：每次贴多少文本、对话里残留多少上文，全凭手感。文本量一失控，产出就变差。换成本地 Agent 后，每一步的输入可以写死（本集剧本 + 资产表 + 工作提示词），每一步用全新的上下文，审查也变成自动跑的一环。所以这两个痛点可以一起解决。

### B. 角色一致性靠文字描述撑不住

已有的资产卡工作流（见 [references](../references/README.md)）里写着"整张重画必换脸""根治靠图生图"。要让角色跨镜头不变脸，有效的办法是把确认过的资产图作为参考图传给模型。新系统应该以"确认过的图"为准，并记录每张分镜图用了哪几张参考图。

### C. 没有状态记录

现在没有任何地方记着：哪张卡出过图、采用的是哪一版、哪些镜头用了它。改一个角色的设定后，哪些下游产物要重做，只能靠人记。

### D. 不知道时间花在哪

没有一集的耗时、返工次数数据。先自动化哪一步，目前是凭感觉。做第一集对比时要顺手记下来，见[新旧流程对比](05-新旧流程对比.md)。
