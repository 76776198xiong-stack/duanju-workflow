# 04 待确认问题

问清楚一条，就把答案写回对应文档，并从这里删掉。

## 背景

材料清点后，我们一度判断朋友的材料凑不成完整流程。但他发来的资产图和他 GitHub 仓库里的人物卡模板完全对得上，效果也好，说明至少资产这一段是完整、在用的。其余部分是否也完整，由第二轮测试来验证（见[第一次测试](05-第一次测试.md)末尾），不再靠读文件猜。

## 现阶段的重点

当前只确定一件事：Codex 能否代替 Gemini，把洛洛的资产卡做到朋友的水平（见[第一次测试](05-第一次测试.md)第二轮）。下面的问题都排在这之后。

## 之后要向朋友要的

1. 一张**故事板图**（线稿草图）。
2. 生成它时交给生图模型的**提示词**。有可能没有单独的提示词，而是直接把镜头表里的内容交给生图模型，那就要一份对应的镜头表。

暂时不研究：Updream 里 @ 名称和图片怎么绑定。

顺带可问：

- 压缩包里有两套视频规则（Five-Dimension Storyboard v8.2，和 jimeng-multishot-storyboard-director），哪套是现行的？

## 其他要问朋友的

5. 你的 GitHub 仓库是用本地 Agent 跑出来的（多个子代理、本地脚本），日常却是 Gemini 网页版手动操作。这两者是什么关系？那 215 张卡现在在用吗？
6. 第一集你自己做的资产图和分镜图能发来吗？用来和 Codex 的结果对比。
7. 在 Gemini 里用的是哪个模型（文字、生图）？生分镜图时会不会把资产图一起传进去作参考？
8. 文字和图片不在 Updream 里做，具体是哪里不行：贵、效果差，还是不好控制？
9. 在 Updream 里"把图片和人物名称链接起来"具体怎么操作？一个镜头要传几张图、链接几处？最好录一段屏。
10. "文本量没把控好"具体指什么：一次贴了多集、单集太长，还是对话太长后质量下降？
11. 分集有没有规则？一集多少字、出多少镜头，有没有测过？
12. 审查通常挑出什么问题？举三五个例子。
13. 一集从剧本到成片大概多久，时间主要花在哪？目前做完了多少集？
14. 你看中的同行工作台是哪个？

## 方向

15. 已定：走技能包路线，不用带界面的现成工作台（它们的重心是接模型、让人在画布上操作，和我们要的监控审核不一样）。先试 drama-skills。
16. 生图用 OpenAI 的 API 密钥走套件的接口，还是用 Codex 自带的生图工具？
17. drama-skills 可以通过接口调用 Seedance。和在 Updream 网页里生成相比，哪个便宜？
18. 朋友仓库里的"关键帧"和我们说的"分镜图"是不是一回事？

## Codex 的意见

### 2026-11-14：第二轮开始前的故事板核查

已读新增三个问题；本次只核查材料，未启动第二轮。核查范围：压缩包解压后的 Markdown/TXT，以及其中6份有效 Word 文档。

1. **故事板的定义**：`五维镜头优化Skill-原始参考/asset_binding_rules.md.docx` 第11段原文：“故事板仅用于确定空间站位和叙事顺序；角色、场景、道具的外观均不以故事板为准。”同目录 `SKILL.md.docx` 第27段重复此规则。两文件没有说明故事板是否为图片、线稿或彩图，也没有规定一镜一张或多格拼图，不能据此定格式。
2. **产出环节与工作提示词**：`SD2.5分镜智能体_可直接移交_v2.1/09-五维镜头优化Skill调用说明.md` 将正式输出明确为“镜号｜时长｜景别／机位／运动｜画面与动作｜对白／音效”的文字表格。已查材料中未找到把该表变成故事板图片的工作提示词或明确生成步骤。断点在镜头表到故事板图片的交接；不能用第一轮关键帧流程补上。
3. **@锚点的职责与图种**：绑定规则第11段明确“外观以专用@锚点为准，叙事顺序以故事板为准”；第14—15段要求绑定块只列本容器实际出场的人物、场景、核心道具的纯实体名称。它没有规定这些锚点具体用资产卡还是单视角图，也未给出素材文件与名称的映射表。第13段“严禁出现 @为故事板: 行”只约束该绑定块写法，不能推导为故事板不用上传或不用参与生成。

另有版本衔接问题：同目录 `SKILL.md` 是 Five-Dimension Storyboard v8.2，`SKILL.md.docx` 却是 jimeng-multishot-storyboard-director；前者是 B-ID/G-ID 平台封装，后者写4—6个、优先5个19—25秒容器。这不是同一文件的两种扩展名。连接层明确指向v8.2，故事板职责条款却出现在Word那套；现有文件未明确两套规则如何接用。

朋友仓库的 `asset-card-template-zh.md` 第9—10行区分给人看的资产设定集与不带标签的关键帧参考，第163行明确“参考用单视角干净图（无格线、无标签、无文字），一镜一图”。这是资产侧规则，不能据此补出视频侧故事板的格式或生成步骤。

需要补齐的原始依据：一份实际使用的故事板样例、生成它的工作提示词，以及一个已完成视频容器的素材绑定示例。先看原件，随后才能判断这里是漏文件、漏步骤，还是版本衔接说明不足。
