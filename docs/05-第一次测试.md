# 05 第一次测试：用 drama-skills 把第一集做到出图

状态：方案已定，等负责人说"开始"。

## 目的

1. 看开源套件 [drama-skills](../references/开源套件-drama-skills.md) 在 Codex 里跑出来的图片效果如何。
2. 摸清这套流程实际怎么走：哪里自动，哪里会停下来问人，花多少时间和钱。

做出来的图发给朋友，由他和自己用 Gemini 做的结果对比。

## 范围

- 材料：《萌娃心声》第一集（本地已提取的 `EP001.md`，1814 字）。
- 做到：资产图和分镜图。视频提示词只写文字，**不生成视频**。
- 套件原样使用，不改任何技能文件。朋友改过的那版资产技能这一轮不用，一次只变一个因素；要不要换上它，下一轮再比。

## 开始前要定的三件事

1. **生图走哪条路。** 套件的生产技能自带 GPT Image 2 的接口适配，需要 OpenAI 的 API 密钥，按量付费，能指定尺寸，参考图的绑定有记录。没有密钥的话，退一步用 Codex 自带的生图工具，照着技能写出的提示词出图，缺点是不能指定尺寸。两条路都可以，用了哪条要记下来。
2. **画幅。** 成片是竖屏 9:16 还是横屏 16:9。朋友的资产卡是 16:9，成片画幅不清楚。不确定就先按 9:16，并记录。
3. **画风。** 沿用朋友的要求：3D 国漫 CG，半写实，不要真人质感。

## 步骤

每一步用套件对应的技能。在本地新建一个项目文件夹，不放在本仓库里。

| 步骤 | 用哪个技能 | 产出 |
|---|---|---|
| 1 建项目 | `$short-drama` | 项目骨架，写入画幅和画风 |
| 2 剧本 | `$short-drama-write` | 把现成的第一集规范化成 `剧本.md`，保留原文，不改写 |
| 3 视觉设定 | `$short-drama-assets` | `视觉设定.md`：本集人物、造型、地点、道具 |
| 4 资产提示词 | `$short-drama-image-prompts` | `图片提示词.md` |
| 5 出资产图 | `$short-drama-produce` 或 Codex 自带生图 | 每个资产 2 张 |
| **停：人审资产图** | | 负责人选定每个资产采用哪一张 |
| 6 分镜 | `$short-drama-storyboard` | `分镜.md`，每个镜头带关键帧提示词，绑定已采用的资产图作参考 |
| 7 出分镜图 | 同第 5 步 | 前 8 个镜头，每个 2 张，实际传入参考图 |
| **停：人审分镜图** | | |

套件的生产技能每次花钱前会要求确认，这是它的设计。第 5、7 步的确认由负责人给。

## 规则

- 不改技能文件。记录套件的版本号。
- 技能中途停下来提问时，原样转给负责人，并把这次提问记进记录表。不要替负责人回答。
- 每个提示词出 2 张图，全部保留，不挑选。
- 生图失败或被拒绝时如实记录，不绕过。
- 剧本、图片、项目文件都留在本地，不提交到仓库。仓库里只放记录。

## 朋友怎么评

逐张给"采用 / 要改 / 不能用"，写一句原因，并和自己用 Gemini 做的同一内容比：更好、差不多、更差。

| 类别 | 看什么 |
|---|---|
| 资产图 | 像不像这个角色；年龄和体型对不对（本剧有萌娃和非人角色）；画风；多视图是不是同一个人 |
| 分镜图 | 是否是镜头的起始画面；构图是否表达了剧情；角色和资产图是不是同一个人；场景是否连贯；镜头拆得合不合理 |

## 第二轮：把洛洛的资产卡调到朋友的水平（待开始）

### 目标

回答当前唯一要确定的问题：**Codex 能不能代替 Gemini 完成工作。** 标准是朋友发来的那张洛洛设定卡：Codex 出的图要达到那个程度。朋友的图是用什么工具做的不重要。

本轮只做资产卡，只做洛洛一个角色。镜头表、故事板、视频提示词都不做。

### 规则来源

朋友 GitHub 仓库的人物卡模板和技能（快照在 `references/upstream/`），主要是 `skills/short-drama-image-prompts/references/asset-card-template-zh.md`。

### 步骤

**第 1 步：先分清差距在哪。**
如果朋友发来的成品里有洛洛这张卡的提示词原文，先把它原样交给 Codex 的生图工具出一张图，16:9，尺寸取最大。

- 这张图接近朋友的：生图工具没问题，后面只需要让 Codex 写出同样水平的提示词。
- 这张图差很多：问题在生图工具，先解决这个，再谈提示词。

没有提示词原文就跳过这一步，并记录"未做"。

**第 2 步：Codex 自己写。**
按朋友的模板和技能，根据第一集剧本，由 Codex 写洛洛的资产卡提示词，再出图。

**第 3 步：对照、修改、重出。**
每出一张，和朋友的图逐项对照，找出差距最大的一两项，只改这一两项对应的提示词，再出。最多 5 轮。

### 对照清单

| 项目 | 标准 |
|---|---|
| 版式 | 左侧面部特写、中间四视图、右侧表情和头部细节和色板、底部动态参考和局部细节和线稿和比例尺，各区齐全，位置对 |
| 四视图 | 正、左、右、背四个朝向都有；两个侧面朝向相反；放大看是同一张脸、同一套衣服 |
| 表情 | 三格表情肉眼能分清 |
| 识别特征 | 泪痣、发饰、挂件等特征在各个视图里都在、位置一致 |
| 文字 | 中文标签没有错字、乱码；色号和色块对得上 |
| 画风 | 3D 国漫 CG，不是真人照片感，也不是低幼卡通 |
| 精细度 | 发丝、布料、绣纹的细节程度接近朋友的图 |

### 每轮记录

追加到 `docs/06-第一次测试记录.md`：这一轮改了什么、对照清单每项是否达标、图片实际尺寸。图片留在本地，发给负责人看。

### 怎么算结束

- **达标**：负责人看图认为达到朋友的水平。结论：Codex 可以代替 Gemini 做资产这一段。
- **5 轮后仍不达标**：写清楚卡在哪几项，是提示词能改的，还是生图工具做不到的（比如中文标签总出错、四视图总不一致、尺寸上不去）。

如果最后是生图工具做不到，也不等于方案失败：可以让 Codex 负责写提示词和调度，生图改为通过接口调用别的生图模型。人仍然不需要复制粘贴。
