# 05 第一次测试：在 Codex 里把朋友的流程走一遍

状态：方案，尚未执行。

## 目的

1. 看 Codex（写文字和生图都由它完成）的结果，和朋友用 Gemini 的结果差多少。
2. 看朋友现有的这套逻辑和提示词本身有没有问题。

## 做法

用《萌娃心声》第一集，**完全按朋友现有的流程和提示词**在 Codex 里走一遍，到出图为止。不优化提示词，不改流程。

对照方式：我们只做 Codex 这一份。做完把图发给朋友，由他和自己用 Gemini 做的结果对比。

## 步骤

### 第 0 步：清点材料

1. 清点朋友给的三样材料（GitHub 仓库快照、压缩包"做漫剧分镜"、七海画布文件），把索引写到 `references/材料索引.md`：每个文件一行，写文件名、是什么、属于流程的哪一步。
2. 指出朋友流程里每一步用的是哪份提示词：分镜、资产、审查、视频提示词。
3. 回答[待确认问题](04-待确认问题.md)第 1 到 4 条。缺材料或有多套冲突就停下来报告，不要自己挑一套或自己补写。

第 0 步做完，等负责人确认后再往下。

### 第 1 步：走流程

每一步都用全新的上下文（对应朋友的"新开对话"），输入只有该步的工作提示词和必要材料。

| 步骤 | 输入 | 产出 |
|---|---|---|
| 资产提示词 | 第一集剧本 + 资产工作提示词 | 资产提示词（审查前） |
| 审查资产提示词 | 上一步产出 + 审查提示词 | 审查意见 + 资产提示词（审查后） |
| 分镜提示词 | 第一集剧本 + 分镜工作提示词 | 分镜提示词（审查前） |
| 审查分镜提示词 | 上一步产出 + 审查提示词 | 审查意见 + 分镜提示词（审查后） |
| 资产生图 | 审查后的资产提示词 | 资产图 |
| 分镜生图 | 审查后的分镜提示词（是否带资产图作参考，按朋友的做法） | 分镜图 |
| 视频提示词 | 按朋友的做法 | 视频提示词（只产出文字，本次不做视频） |

以上步骤以朋友材料里的实际流程为准，清点后发现不一致就按材料改。

### 第 2 步：交付

- 把全部资产图和分镜图按编号整理好，交给负责人转发给朋友。
- 填写下面的记录表。

## 规则

- **保存每一步的中间产物**，审查前和审查后的版本都留。人不审文字，但出了问题要能回头查是哪一步造成的，也能看出审查环节到底改了什么。
- 每个提示词出图 2 张。全部保留，不挑选。
- 不手改任何提示词。生图失败或被拒绝时如实记录，不绕过。
- 记录实际使用的模型名称和日期。
- 剧本、图片、中间产物放在本地，不提交到仓库。仓库里只放记录表。

## 朋友怎么评

逐张给"采用 / 要改 / 不能用"，写一句原因，并和自己用 Gemini 做的同一内容对比：更好、差不多、更差。

| 类别 | 看什么 |
|---|---|
| 人物资产图 | 像不像这个角色；年龄和体型对不对（本剧有萌娃和非人角色）；画风；多视图是不是同一个人 |
| 分镜图 | 动作和构图是否表达了剧情；角色跨镜头有没有变脸；场景是否连贯；分镜拆得合不合理 |

## 测完之后

- 结果不比 Gemini 差：全部搬到 Codex，进入提示词优化和流水线。
- 文字可以、生图不行：Codex 负责文字和调度，再看生图怎么解决。
- 都不行：先查中间产物，分清是模型的问题还是提示词需要针对 GPT 调整。
